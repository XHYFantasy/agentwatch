# 看不懂 AI 在电脑上干什么？把它每一步翻成人话，送到你手机上

**AI 监看** · 在手机上看着电脑上的 AI agent 干活。

它每要动一次手，手机上弹一条**中文**通知告诉你「要批准什么」—— 你可以直接在通知上点
原生按钮批准或拒绝。另有一条常驻通知实时显示「AI 干到哪了」。

> **想解决的问题**：让 AI 去跑长任务的时候，人不用守在电脑前。
> 但**不是**「闭眼放行」—— 该拦的照样拦，只是拦在手机上，而且拦之前先告诉你它在干什么。

---

## 长什么样

手机通知栏上会有两种：

| | 内容 |
|---|---|
| **常驻条** | `AI 监看 · 监听中 · 21:02 已同步` —— 时间是心跳，在走就说明链路活的 |
| **待批条** | `需要批准 · 向工作区外文件写入`，展开是风险等级 / 目标路径 / agent 自己给的理由 |

点待批通知直接跳到那条审批所在的会话，在原生界面上点「批准」或「拒绝」。

有 `n` 条待批时，常驻条自己会改口成 `⚠️ 需要你批准 · 有 n 条待你批准` ——
因为很多 ROM 会把同一个 App 的通知折叠起来，折叠那一眼看到的往往只有标题。

---

## 它是怎么拼起来的

| 部件 | 是什么 | 干什么 |
|---|---|---|
| `plugin/agentwatch-card/` | dsh 插件 | 把审批请求翻成大白话；对外提供「现在有几条待批」 |
| `android/` | Android App | WebView 壳 + 常驻服务：轮询、发通知、把批准/拒绝打回去 |
| `tools/ts-bridge.mjs` | 中转 | 把只监听 `127.0.0.1` 的 dsh 透传到 Tailscale 网段 |

[dsh](https://github.com/deepseek-ai)（DeepSeek Harness）是宿主：会话、审批协议、
界面都在它那边。**本项目不重画会话流** —— dsh 原生已经把「思考 / 工具调用 / 结果」
渲染得很完整了，再画一遍就是同一个东西在屏幕上出现两次。翻译只落在
**原生审批卡内部的那一个格子**里。

## 从源码构建

见 [安装说明.md 的「附：给开发者」](安装说明.md#附给开发者)。

一句话版：

```powershell
# 1) 填地址（不填会直接构建失败 —— 这是故意的，见下）
#    android/local.properties 里加一行：agentwatch.host=100.x.y.z
#    地址用 tailscale ip -4 查

# 2) 构建（可加 -Install 直接装到设备）
.\构建APK.ps1 -Release
```

> **为什么没填地址要故意构建失败？**
> 因为「地址没换」这个故障的症状是 **App 打开一片黑、一条错都不报** ——
> 看起来像服务端坏了，能查半天。
> 给它一个默认值确实能编过，但装到手机上是一条永远连不上的死路 ——
> 那等于把「你配置漏了」伪装成「服务端有问题」。宁可当场停下来把话说清楚。

## 安全上的取舍

- **不暴露任何公网端口。** 手机连的是 Tailscale 网段里的地址，链路本身由 WireGuard 加密。
- **凭据不落地。** 认证走 WebView 里 dsh 自己发的 cookie；App 里不存 token、不存 key。
  电脑上那几个含明文凭据的文件（`~/.claude/settings.json` 之类）**一律不直连**。
- **明文 HTTP 是有意为之。** 链路已经被 Tailscale 加密，再套一层 TLS 只是多一个证书要维护。
  Android 的明文白名单**只放行你填的那一个地址**，其余一律禁止。

## 已知限制

这些都是实测撞出来的，写在这里省得你重复撞：

- **只在 Android 上验过，而且主要是一台 vivo 手机。** 国产 ROM 的后台管理差异很大。
  vivo 上「切后台 10 秒冻结进程」「划掉卡片 = 强制关闭」「通知被自动分组折叠」三条都踩过；
  AOSP 那套「电池优化白名单」在 vivo 上**完全不管用**，只有厂商自己的白名单管用。
  别的机型大概率要重新调一遍保活。
- **iOS 没做。** 常驻后台 + 本地通知这套在 iOS 上走不通。
- **为单机自用设计**，没做多用户、多设备、权限体系。
- **审批界面是 dsh 原生的**，本项目不重画（理由见上）。
